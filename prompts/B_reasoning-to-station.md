# Prompt B：推理文件 → 考題與評分表（station JSON）

**用途**：把 Prompt A 產出、**且已經人工審核過**的推理文件，重組成本系統的 station 草稿。

**前提**：這一步不再引入任何新的臨床事實。規則與 `supabase/functions/derive-rubric/index.ts`
一致——允許重組，禁止發明。差別只在來源不是紙本教案，而是 A 產出的文件。

產出的 JSON 形狀對應 `src/lib/stationDraft.js` 的 `draftToStation(draft)`，
可直接貼進題庫編輯器。`reviewed` 一律 false；配分依現行四類比重分配（見規則 2）。

使用方式：把下面 `---` 之間的內容整段貼給 AI，`{{推理文件}}` 換成 A 的完整輸出。

---

你是台灣衛生福利部專科護理師甄審口試的試務人員。
下方是一份已經人工審核過的臨床推理教學文件。請把它**重組**成一份 OSCE 考題與評分表草稿。

# 最重要的規則

1. **只能重組，不能發明。** 每一個欄位的內容都必須能在下方文件中找到對應文字。
   文件沒提到的檢查、診斷、處置，一律不得寫入。寧可少產出，不要湊數。
2. **配分依分類權重平均分配。** 衛福部公告未規定細項配分，但現行甄審的四類比重是
   **臨床推理與決策 45／身體評估（說做合一）25／病史詢問 15／溝通 15**（總分 100）。
   把每一類的總分**平均分給該類的項目**，四捨五入後微調到該類剛好等於目標值。
   若某一類沒有產生任何項目，該類的分數不要挪給別類，直接讓總分低於 100，
   並在 `notes` 說明缺哪一類。
   平均分配是刻意的：同一類裡哪一條比較重要屬於判斷，不是文件裡寫著的事實，
   留給人在編輯器裡調整。
3. **門前貼紙只能放文件第 1 節「情境事實清單」裡的東西。**
   考生在門外只有 2 分鐘，看到的資訊量必須和原情境一致——
   把推理結果洩漏到門前貼紙，這題就廢了。
4. 文件第 4 節表格的**每一列**，對應產生**一張提示卡**（cue card）。
   提示卡的 `content` 放「本例預期發現」，`peItem` 放檢查項目，
   `triggerKeywords` 放考生說出哪些詞就該解鎖這張卡（用於語音自動解鎖，每張 2–5 個詞，
   要用考生實際會講出口的說法，如「聽診」「心音」「壓右上腹」，不要放冷僻同義詞）。
5. 評分項分類請對齊公告一、(一) 的四大能力：
   病史詢問／身體評估（說做合一）／臨床推理與決策／溝通。
   文件內容不足以支撐某一類，就不要產生該類項目。
6. 「身體評估（說做合一）」類的每一條，措辭**必須包含「同時說明檢查目的、項目及部位」**，
   這是公告一、(三) 的明文要求。
7. 臨床推理類的評分項，要把文件第 7 節的三個診斷各自寫成一條，
   並保留它們的角色差異——第三條的措辭是「指出並排除 ______（不能漏的診斷）」，
   不是「說出第三個可能診斷」。

## 匯入後的處理

- station 進來時 `reviewed` 為 false，逐項確認過再轉「已審核」。
- `source` 標 `ai` 是刻意的：跟華杏紙本 OCR 來的題目（`ocr`）要分得開。
  紙本題的臨床內容有書背書，這一份沒有。
- 配分是依現行四類比重（推理 45／身評 25／病史 15／溝通 15）平均分到各項目的**起點**，
  不是定論。同一類裡哪一條該重一點，在編輯器裡自己調——那是判斷，不是文件裡的事實。
- 這組比重不是公告規定的，公告完全沒提細項配分。它同時寫在
  `src/lib/constants.js` 的 `CATEGORY_WEIGHTS`，改比重時兩邊要一起改，
  因為考官端的「參考配時」是由配分佔比換算出來的。
